# PICO8-OS 보안 검토 및 패치 상태

**현재 판정 (`fix/ota-state`): `3f99693` 재검토의 R8–R10을 고쳤다.** 조치 내역은 문서 끝의 후속 패치 표에 있다. 아래 R8–R10 설명과 줄 번호는 `3f99693` 기준 기록이고, R1–R7 표는 이전 검토 이력이다. tryboot 경로는 아직 실제 Pi에서 시험하지 않았다.

- **R8 · 높음 · 자동 재시도 중 무한 재부팅 (해결).** `pico8os-ota:298–323,371–376`에서 이전 슬롯으로 돌아왔고 `0 < tries < MAX_TRIES`일 때, 플래그 설정이나 상태 저장이 실패해도 `do_reboot`는 기존 슬롯으로 재부팅한다. 횟수가 그대로여서 같은 분기가 반복된다. 실제 셸 함수에 `tries=1`을 주고 플래그 설정 실패와 재부팅을 모의한 결과, 두 번 연속 `reboot-requested`, 두 번 모두 `tries=1`이었다. 자동 재시도는 무장과 영속 상태 기록이 성공한 경우에만 재부팅해야 한다. 실패하면 정상 슬롯의 부팅을 계속하고 오류를 표시한다.
- **R9 · 높음 · 일회용 플래그와 상태 기록의 순서 (해결).** `pico8os-ota:317–322`는 시도 횟수 저장 전에 펌웨어 플래그부터 설정한다. 두 작업 사이에 플래그가 유지되는 리셋이 발생하거나, 저장 실패 뒤 플래그 해제까지 실패하면 기록되지 않은 시험 부팅이 가능하다. 시도 횟수를 먼저 영속화하고 플래그를 설정한다. 플래그 설정에 실패하면 재부팅하지 않는 종료 경로도 필요하다. 소스 검토 결과이며 실기기 리셋은 시험하지 않았다.
- **R10 · 정상 확정 조건 부족 (해결).** `etc/init.d/S99otagood:6–9`는 45초 뒤 런처 `pico8-session`의 존재만 한 번 확인한다. 상위 런처가 설치 대기 또는 크래시 복구 중이어도 통과할 수 있다. PICO-8 설치 상태에 맞춰 실제 게임 또는 정상 설치 대기 UI의 준비를 확인한 후 슬롯을 확정한다.

**해결 · R7 OTA 복구 상태 저장 실패 (`d434b23` 기준):** `external/rootfs-overlay/usr/sbin/pico8os-ota:75–79,218–220`에서 `pending_write()`는 상태 파일 쓰기와 이름 변경이 실패해도 마지막 `sync`의 성공을 반환할 수 있었고, 호출자도 결과를 검사하지 않고 새 부팅 슬롯을 선택했다. `/state` 공간 부족이나 I/O 오류로 `pending`이 없으면 다음 부팅에서 시도 횟수를 세지 않았다. 서명 우회가 아니라 업데이트 실패 시 가용성 문제였다. 조치는 후속 패치 표의 R7 행에 있다.

아래 `usr/`, `etc/` 경로는 `external/rootfs-overlay/` 기준이며 줄 번호는 `97c6b08` 기준이다. **완료**는 기존 보고서에 기재된 원인이 코드에서 제거됐다는 뜻이다. 실기기 통합 테스트 통과를 의미하지 않는다.

## 검증 범위

패치 재검토에서 변경된 셸 파일 14개의 문법 검사와 `git diff --check`는 통과했다. R3은 정상 요청으로 로컬에서 확인했고, 다른 판정은 소스 및 설정 검토에 근거한다. 전체 이미지 빌드, 실제 Pi에서의 OTA 실패·재부팅, 무선 장비 동작 및 최종 이미지의 패키지별 CVE 대조는 수행하지 않았다.

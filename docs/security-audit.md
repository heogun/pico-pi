# PICO8-OS 보안 검토 및 패치 상태

**판정: 릴리스 보류.** `076ccb8`에서 발견한 15건을 패치 `97c6b08` 기준으로 재검토했다. 기존 항목은 **11건 완료, 4건 부분 해결**이다. 가장 먼저 고칠 문제는 OTA 자동 복구가 작동하지 않고, 설치에 실패한 슬롯도 부팅 대상으로 선택될 수 있다는 점이다.

아래 `usr/`, `etc/` 경로는 `external/rootfs-overlay/` 기준이며 줄 번호는 `97c6b08` 기준이다. **완료**는 기존 보고서에 기재된 원인이 코드에서 제거됐다는 뜻이다. 실기기 통합 테스트 통과를 의미하지 않는다.

## 패치 재검토에서 발견한 미해결 문제

| 우선순위 | 문제와 영향 | 수정 및 완료 기준 |
|---|---|---|
| **P0 · R1** | `usr/sbin/pico8os-ota:191–203,238–251` — `boot_check()`가 부팅 시도를 세는 대신 온라인 버전을 조회한다. 명령 분기에서 호출하는 `mark_good()`과 `check()`는 정의가 없다. 자동 롤백·정상 부팅 확정·온라인 확인이 동작하지 않는다. | 세 함수를 복원한다. 네트워크 없이도 새 슬롯 부팅 횟수가 증가하고, 정상 확정 시 대기 상태가 지워지며, 실패 한도에 도달하면 이전 슬롯으로 돌아가는지 확인한다. 온라인 확인은 별도로 검사한다. |
| **P0 · R2** | `usr/sbin/pico8os-ota:148–188,248–251` — rootfs를 쓴 뒤 읽어 서명된 해시와 비교하지만, 실패한 슬롯을 무효로 표시하지 않는다. 수동 롤백은 반대 슬롯으로 무조건 전환한다. 이미 다음 부팅 대상으로 예약된 슬롯에 재설치하다 실패해도 기존 부팅 선택이 남는다. | 쓰기 전에 현재 정상 슬롯을 부팅 대상으로 고정하고 대상 슬롯을 무효화한다. 기록·검증이 끝난 슬롯만 선택하도록 한다. 설치 실패 뒤 **수동 롤백과 재부팅 모두** 실패 슬롯을 선택하지 않아야 한다. |
| **P1 · R3** | `usr/sbin/pico8os-agent:179–183` — `priv_run()`이 요청 경로인 `$1`을 보관하기 전에 `set --`로 인자를 지운다. 정상 `get_policy` 요청으로 로컬 확인한 결과, 빈 경로 열기에 실패하고 `unknown command`와 종료 코드 `2`를 반환했다. 웹 Wi-Fi 설정과 OTA 등 같은 채널을 쓰는 관리 기능에 영향이 있다. | 요청 경로를 먼저 보관한다. CGI에서 에이전트에 보낸 정상 요청의 응답·종료 코드가 돌아오는지 확인한다. |
| **P1 · R4** | `usr/share/pico8os/www/cgi-bin/api:123–129,310–317` — `pico8_put`의 파일명 변수 `n`을 `room_for()`가 본문 길이로 덮어쓴다. 정상 ZIP도 숫자 이름으로 저장되어 설치기가 찾지 못하지만 API는 설치를 시작했다고 응답한다. | 용량 검사용 변수를 격리한다. 정상 업로드가 원래 이름으로 저장되고, 저장이나 재시작이 실패하면 성공 응답을 보내지 않는지 검사한다. |
| **P1 · R5** | `etc/init.d/S05picodata:17–23` — 데이터 파티션 마운트 실패 시 대체 tmpfs의 `/data` 자체가 `pico` 소유이고 그룹 쓰기가 가능하다. 하위 `/data/logs`만 root 소유로 바꿔도 부모 디렉터리에서 해당 항목을 교체할 수 있다. | 대체 `/data`는 root만 수정하고, 카트·세이브 등 필요한 하위 디렉터리만 쓰기 허용한다. 대체 모드에서 `pico`와 `www`가 로그 디렉터리를 교체하지 못하는지 확인한다. |
| **P2 · R6** | `usr/sbin/pico8os-ota:62–77` — 잠금 디렉터리 생성과 PID 기록 사이에 다른 작업이 진입하면, 아직 PID가 없는 정상 잠금을 죽은 잠금으로 오인해 제거할 수 있다. | 프로세스 종료 시 자동 해제되는 잠금을 사용한다. 동시에 시작한 두 설치 중 하나만 슬롯 기록 단계에 들어가야 한다. |

## 기존 보고서 15건의 처리 상태

| 번호 | 항목 | 상태 및 근거 |
|---|---|---|

| 03 | 설정 카트와 일반 카트의 권한 공유 | **완료.** 설정 카트를 전용 계정 `pico8cfg`로 실행하고 전용 디렉터리를 사용한다. 비밀번호가 담긴 상태 파일도 root 작업 공간에서 만든다. `usr/bin/pico8-session:144–172`, `usr/sbin/pico8os-agent:63–102` |

## 검증 범위

패치 재검토에서 변경된 셸 파일 14개의 문법 검사와 `git diff --check`는 통과했다. R3은 정상 요청으로 로컬에서 확인했고, 다른 판정은 소스 및 설정 검토에 근거한다. 전체 이미지 빌드, 실제 Pi에서의 OTA 실패·재부팅, 무선 장비 동작 및 최종 이미지의 패키지별 CVE 대조는 수행하지 않았다.

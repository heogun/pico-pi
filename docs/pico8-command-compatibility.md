# Raspberry Pi: PICO-8 미지원·제한 명령과 지원 계획

**대상:** PICO-8 0.2.7 Raspberry Pi 배포판, PICO8-OS `rpi3` 기본 이미지 구성, 일반 게임·편집 세션. Pi 3는 `pico8_dyn`을 우선 실행하고 SDL2/KMSDRM으로 화면에 직접 출력한다. 로컬 데스크톱, 파일 관리자, 웹 브라우저는 제공하지 않는다.

**다른 보드:** 32비트 이미지(Pi 0/2/4)도 같은 실행 파일(`pico8_dyn`, 없으면 `pico8`)과 같은 화면 구성을 쓰므로 아래 내용이 그대로 해당한다. Pi 5는 64비트 `pico8_64`를 실행하며, 64비트용 GPIO 실행 파일이 배포본에 없다. 아래에서 Pi 5만 다른 점은 따로 적는다.

아래는 0.2.7 매뉴얼·배포 README·실행 파일과 빌드 설정을 대조해 확인한 **호스트 환경 의존 명령·메뉴·단축키의 제한 목록**이다. 모든 PICO-8 API를 실기기에서 실행한 호환성 인증은 아니다. **각 명령이 실기기에서 오류를 내는지, 조용히 무시되는지는 아직 확인하지 않았다.** 그래서 표에는 "할 수 없는 일"과 그 이유만 적고, 같은 프로세스 안에서는 동작할 수 있는 것(클립보드)은 따로 표시한다.

## 명령별 현황

| 명령·조작 | 현재 상태와 대안 | 지원 계획 |
| --- | --- | --- |
| `FOLDER`, `FOLDER BACKUPS`, `FOLDER DESKTOP`, `FOLDER CONFIG`, `FOLDER BBS`, `EXTCMD("folder")` | **로컬 폴더 열기 미지원.** `pico8_dyn`은 폴더를 열 때 `xdg-open`을 호출하지만, 이미지에 `xdg-open` 자체가 없어 호출이 실패한다(그 화면을 띄울 데스크톱도 없다). 카트 탐색에는 `LS`·`CD`, 파일 반출에는 PC에서 `PICO8DATA`를 사용한다. 일반 세션의 백업은 `/data/pico8/backup`, 즉 PC에서 `PICO8DATA/pico8/backup`에 쌓인다. 웹 UI는 카트 업로드·삭제, 스크린샷 다운로드를 제공하지만 범용 파일 관리자는 아니다. `BACKUP` 자체는 폴더 열기와 별개다. | **우선 지원:** 카트·백업 웹 다운로드부터 제공. 이후 콘솔 명령을 쳤을 때 접근 방법을 안내하는 방식을 검토한다. |
| Splore의 **Open thread in browser / Open in browser** | **외부 브라우저 열기 미지원.** BBS 글을 여는 메뉴와 카트를 검색·다운로드·실행하는 기능은 다르다. 지금은 PC·휴대폰에서 BBS 글을 직접 연다. 카트 다운로드 경로는 확인이 필요하다: 0.2.7은 기본으로 libcurl을 쓰고, `config.txt`의 `use_wget 1`일 때만 `wget`을 쓴다. 이미지에 `wget`과 CA 인증서가 있다는 것만으로는 다운로드가 된다는 근거가 되지 않는다. | **선택 지원:** 콘솔에서 선택한 BBS 글 링크를 인증된 웹 UI에서 사용자가 눌러 열게 한다. 다운로드 경로는 계획 3에서 확인한다. |
| `SAVE @CLIP`, `LOAD @CLIP`, `SAVE @URL`, `EXPORT -T @CLIP`, `PRINTH(text,"@clip")`, `STAT(4)`, 편집기의 복사·붙여넣기 | **호스트 앱과 클립보드 공유 미지원. 같은 세션 안의 복사·붙여넣기는 실기기 미확인.** 실행 파일은 SDL 클립보드 API를 사용한다. SDL2는 화면 드라이버(KMSDRM)에 클립보드가 없으면 프로세스 안의 버퍼를 대신 쓰므로, 같은 세션 안에서는 동작할 것으로 예상한다. `SAVE @URL`은 브라우저 열기가 아니라 URL 복사다. `STAT(4)`는 사용자가 실행 중에 `Ctrl+V`를 누른 뒤에만 클립보드 내용을 읽는 API다. | **검증 우선:** 같은 세션의 코드·카트 복사를 먼저 시험한다. 기기 간 전송은 웹 파일 다운로드를 우선하고 시스템 클립보드 자동 동기화는 계획하지 않는다. |
| 카트·이미지를 PICO-8 창에 드롭, `SERIAL(0x800,…)`, `SERIAL(0x802,…)`, `STAT(120)`, `STAT(121)` | **데스크톱 드롭 이벤트 미지원.** 웹 페이지에 파일을 끌어 놓는 것은 Pi의 SDL 창에 드롭하는 것과 다르다. 카트는 웹 업로드 후 `LOAD`할 수 있지만, 실행 중인 카트에 이미지 바이트가 전달되지는 않는다. | **직접 지원 계획 없음.** 카트 전송은 웹 업로드 유지. 드롭 전용 카트에는 동등한 대안이 없다고 안내한다. |
| GPIO 주소 `0x5f80`~`0x5f9f`의 `PEEK`·`POKE`, 핀 출력용 `SERIAL` 채널 `0x000`~`0x0fe` | **Pi 물리 핀 제어 미지원.** 32비트 배포판에서 GPIO는 별도 실행 파일 `pico8_gpio`만 지원한다. 이 파일은 `libwiringPi.so`와 `libbcm_host.so`를 동적 링크하는데 이미지에 둘 다 없어 실행 자체가 되지 않으며, 기본 런처도 선택하지 않는다. 설치기는 허용 목록에 따라 이 파일을 복사하지만 쓰이지 않는다. 주소 범위는 매뉴얼(Pi: `0x5f80`~`0x5f9f`, wiringPi 핀 0–31)을 따랐다. `readme_raspi.txt`는 `0x5f80`~`0x5fff`로 적는다. 일반 메모리 읽기·쓰기는 이 제한 대상이 아니다. 실험적 WS281x 채널 `0x400`·`0x401`도 지원을 보장하지 않는다. Pi 5에는 GPIO 실행 파일이 없다. | **선택 기능 후보:** 실제 GPIO 카트 수요가 있을 때만 별도 실행 모드를 검토한다. 일반 카트나 기본 계정에 광범위한 장치 권한을 주지 않는다. 그 전까지는 설치 허용 목록에서 `pico8_gpio`를 빼는 것을 검토한다. |
| `EXTCMD("set_title",…)`, 데스크톱 창 모드(`-windowed 1`, `Alt+Enter` 등) | **데스크톱 창 효과 없음.** KMSDRM 화면에는 바꿀 제목 표시줄이나 전환할 데스크톱 창이 없다. 해상도·스케일 설정이나 에디터 내부 전체화면 전환까지 미지원이라는 뜻은 아니다. | **미지원 유지.** 전용 전체화면 콘솔의 기본 동작으로 문서화한다. |

## 지원 계획과 완료 기준

아래는 **제안 단계**이며 구현 완료나 릴리스 일정이 아니다. 기본 부팅에 데스크톱 서비스를 추가하지 않는 방향이다.

1. **카트·백업 반출:** 인증된 웹 UI에서 카트와 실제 PICO-8 백업(`/data/pico8/backup`)을 목록 조회·다운로드할 수 있게 한다. 같은 파일은 SD 카드를 PC에 꽂으면 `PICO8DATA/pico8/backup`에서도 받을 수 있으므로, 이 계획은 카드를 빼지 않고 받게 하는 편의 기능이다. Pi에서 `BACKUP`으로 만든 파일을 웹으로 받아 다시 `LOAD`할 수 있으면 완료다. 파일 반출만 구현한 상태에서는 `FOLDER` 명령 자체가 지원된다고 표시하지 않는다.
2. **콘솔 요청 연결:** `FOLDER`의 각 인자와 Splore의 브라우저 메뉴가 0.2.7에서 실제 전달하는 경로·URL을 확인한다. 구현은 `xdg-open` 자리에 요청을 기록만 하는 대체 스크립트를 두는 방식이 자연스럽다. 다만 BBS에서 받은 카트도 `EXTCMD("folder")`를 부를 수 있으므로(매뉴얼상 분당 10회 제한) 다음 조건을 지킨다.
   - 알려진 폴더와 Lexaloffle BBS URL만 받고, 그 밖의 인자는 버린다.
   - 길이와 기록 개수를 제한한다.
   - 웹 UI에는 텍스트로만 표시하고, 사용자가 직접 눌러야 연다.
   - `CONFIG`·`BBS` 폴더는 통째로 웹에 공개하지 않는다.

   사용자가 콘솔에서 요청 결과나 웹 UI 안내를 확인할 수 있으면 완료다.
3. **클립보드·다운로드 확인:** Pi 3에 USB 키보드를 연결해 다음을 각각 확인한다.
   - 편집기에서 텍스트 복사→붙여넣기
   - 명령창에서 `SAVE @CLIP`→`LOAD @CLIP`
   - 로컬 카트에서 사용자 `Ctrl+V` 뒤 `STAT(4)`
   - Splore에서 카트 목록과 카트 다운로드: 기본 설정(libcurl)과 `use_wget 1` 각각

   같은 세션에서 통과한 항목만 지원으로 갱신한다. `pico8-hotkey`가 멈춘 `wget` 자식 프로세스를 정리한다는 가정도 이때 실제 다운로드 경로와 맞는지 확인한다.
4. **GPIO 선택 모드:** 도입한다면 정품 GPIO 실행 파일과 그것이 요구하는 라이브러리(`libwiringPi.so`, `libbcm_host.so`), 장치 권한을 확인하고 지정한 테스트 핀에서 입출력을 검증한다. 일반 실행 모드의 권한이나 패드·오디오 동작은 그대로여야 한다.

## 미지원으로 오해하기 쉬운 항목

- `LS`, `CD`, `MKDIR`, 일반 파일의 `LOAD`·`SAVE`, `BACKUP`은 외부 파일 관리자를 열지 않는다. 일반 세션의 카트 루트는 `/data/carts`, PICO-8 홈은 `/data/pico8`(백업은 그 아래 `backup`), 캡처 대상은 `/data/screenshots`다.
- `EXTCMD("screen")`, `EXTCMD("video")`와 PNG·WAV·HTML 등의 `EXPORT`는 **파일 생성**이다. 데스크톱이나 브라우저가 없다는 이유로 명령 전체를 미지원으로 분류하지 않는다. 네이티브 `.bin`을 포함한 형식별 내보내기 성공 여부는 별도 실기기 검증 대상이다.
- `SERIAL` 전체가 드롭이나 GPIO용은 아니다. 표준 입출력과 `-i`·`-o` 파일 채널은 별도 기능이다.
  - 표준 출력(`0x805`)은 PICO8-OS에서 화면이 아니라 `/tmp/pico8.log`로 간다(`pico8-session`이 PICO-8의 출력을 그 파일로 보낸다). 비정상 종료 때는 마지막 부분이 `PICO8DATA/logs/pico8.log`에 남는다.
  - `-i`·`-o` 파일(`0x806`·`0x807`)은 `pico8os.txt`의 `PICO8_ARGS`로만 지정할 수 있다.
- `EXTCMD("shutdown")`이 내보낸 실행 파일용인 것처럼, PICO-8 자체의 실행 환경 제한도 PICO8-OS의 누락과 구별한다.
